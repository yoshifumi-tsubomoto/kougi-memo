# 講義メモ（GAS版）

講義・研修・講演会・セミナーなど、長時間（4時間程度まで）の話をまるごと記録し、セッションごとにまとめるアプリです。Google Apps Script（GAS）で動きます。

- **リアルタイム文字起こし**：Chromeの音声認識で、講義中ずっと文字に起こします。途中で止まっても自動で再開します。
- **録音**：約10分ごとに区切って、Googleドライブに保存します。後から高精度で清書するために使います。
- **メモ**：時刻付きで書けます。種類は「メモ・要点・質問・TODO・引用」の5つです。
- **スマホ連携**：PCに出るQRコードをスマホで読むと、撮った写真やメモが数秒でPCの画面に届きます。
- **セッション管理**：「次のセッションへ」で区切ります。時刻はすべて自動で記録されます。
- **まとめと出力**：セッションごとに、好きな文字数で要約できます。Googleドキュメント（写真入り）とテキストで出力できます。

## ファイル構成

```
src/
  Code.gs          保存とサーバー側の処理（スプレッドシートとドライブ）
  Index.html       PCの画面
  Phone.html       スマホの画面
  appsscript.json  GASの設定（自分だけが使うWebアプリ）
tools/
  preview.mjs      GASに上げずに画面だけ確認するための書き出し
  check.mjs        画面を自動で開き、エラーがないかを確認
```

データは、初めて使ったときに自動で作られる場所に保存されます。

```
マイドライブ/講義メモ_データ/
  講義メモ_記録（スプレッドシート：lectures / transcript / memos / audio）
  2026-11-14_講義タイトル_xxxx/   ← 講義ごとのフォルダ
    audio/   録音（10分ごと）
    images/  写真
    （出力したGoogleドキュメント）
```

## はじめての設定

### 方法1：clasp を使う（開発する人向け）

clasp は、このリポジトリのファイルを GAS に送るための Google 公式ツールです。

```bash
npm install
```

```bash
npx clasp login
```

```bash
npx clasp create --type webapp --title "講義メモ" --rootDir src
```

`create` を実行すると `.clasp.json` ができます。既存のプロジェクトを使う場合は、`.clasp.json.example` をコピーしてスクリプトIDを書き込んでください。`.clasp.json` は人によって中身が違うため、Git には入れません。

```bash
npm run push
```

### 方法2：手でコピーする（配布を受けた人向け）

1. https://script.google.com で「新しいプロジェクト」を作る
2. `Code.gs` の中身を貼り付ける
3. 「＋」→「HTML」で `Index` と `Phone` を作り、それぞれ中身を貼り付ける
4. 「プロジェクトの設定」で「appsscript.json をエディタで表示」をオンにし、`appsscript.json` を貼り付ける

### 公開（デプロイ）

1. エディタで関数 `setup` を1回実行し、Googleドライブなどへのアクセスを許可する
2. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」を選ぶ
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**自分のみ**
3. 表示されたURLを、PCのChromeでブックマークする

スマホは、PCと**同じGoogleアカウントでログイン**した状態で、QRコードから開きます。

## 清書（高精度の文字起こし）の方法

清書の方法は、スクリプト プロパティ（エディタの「プロジェクトの設定」→「スクリプト プロパティ」）で切り替えます。学校や個人の事情に合わせて選べるようにしてあります。

| 番号 | 方法 | 設定 | 状態 |
|---|---|---|---|
| ① | 清書なし（リアルタイムの速報だけ） | 設定不要（初期設定） | ✅ 実装済み |
| ② | PCの中で清書（ブラウザ内のWhisper。音声を外部に送らない） | `TRANSCRIBE_ENGINE` = `browser` | 🔜 次に作る |
| ③ | OpenAI で清書 | `TRANSCRIBE_ENGINE` = `openai`、`OPENAI_API_KEY` = キー | 🧪 下書きあり・未検証 |
| ④ | Gemini で清書 | `TRANSCRIBE_ENGINE` = `gemini`、`GEMINI_API_KEY` = キー | 🔜 予定 |

要約はAIを直接呼ばずに、次の流れにしています。どのAIを使ってよいかは学校ごとに違うため、その差に左右されないようにするためです。

1. 「要約用にコピー」を押す（指定した文字数の要約を頼む文章と、文字起こし・メモがまとめてコピーされる）
2. 学校で使えるAI（Geminiアプリなど）に貼り付ける
3. 返ってきた要約を貼り付けて保存する

## 使い方

1. 「新しい講義」を作り、タイトル・講師・会場を入れる
2. 講義が始まったら「● セッション開始」を押し、マイクの使用を許可する
3. 休憩などで区切るときは「⏭ 次のセッションへ」、終わったら「■ 終了」を押す
4. 「📱 スマホと連携」のQRコードをスマホで読み、写真やメモを送る
5. 「まとめ・出力」で、セッションごとに要約し、Googleドキュメントやテキストに出力する

長時間使うときの注意：

- PCは電源につなぎ、スリープしない設定にしてください。
- Chromeの音声認識はインターネット接続が必要です。音声はGoogleに送られます。
- マイクは、講師の声が直接届く位置にあるほど精度が上がります。

## 開発の流れ

```bash
npm run check
```

画面を書き出してブラウザで開き、エラーがないかを確認します（Playwright が必要）。

```bash
npm run preview
```

`preview/index.html` を開くと、GASに上げなくても画面を確認できます。保存先は仮のもので、閉じるとデータは消えます。

```bash
npm run push
```

GASに反映します。その後、エディタの「デプロイを管理」で新しいバージョンにします。

保存先の切り替え（Supabase版）を見すえて、画面からサーバーを呼ぶ処理は `Index.html` の `api` オブジェクト1か所に集めてあります。Supabase版を作るときは、ここを差し替えます。

## まだ確かめていないこと（最初に実機で確認する）

- [ ] **GASのWebアプリでマイクが使えるか**（音声認識と録音）。GASの画面は特殊な枠（iframe）の中で表示されるため、ブラウザによってはマイクが拒否される可能性があります。使えなかった場合は、画面だけを GitHub Pages に置き、GAS はデータの保存専用にする構成に切り替えます。
- [ ] 音声認識と録音を同時に動かしたときに、両方とも止まらずに続くか
- [ ] 4時間連続で動かしたときの、自動再開と保存の安定性
- [ ] スマホからの写真の送信（iPhoneのSafariとAndroidのChrome）
